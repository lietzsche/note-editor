# BACKLOG-004: 모바일 뒤로가기·화면 전환

- 문서 버전: v1.0
- 작성일: 2026-11-05
- 상태: Done (실기기 확인 대기)
- 우선순위: High
- 성격: 모바일 UX 개선

## 1. 문제

모바일에서 휴대폰 뒤로가기 버튼이 앱 안의 화면 전환(그룹/목록/편집)과 연결되어 있지 않았다.
편집 중 뒤로가기를 누르면 목록이 아니라 앱 밖으로 나갈 수 있었고, 저장 전 이탈을 막는 장치도 없었다.

## 2. 동작 규칙 (모바일 전용, PC 동작 변경 없음)

뒤로가기 한 번에 아래 중 가장 위의 하나만 처리한다.

1. 열린 겹침 화면을 닫는다. 나중에 연 것부터 닫는다.
   - 에디터 더보기 메뉴, 노트 행 메뉴, 공유 팝오버, 영구 삭제 확인
   - 전환/충돌 다이얼로그(취소와 동일), 계정 보안 모달, 운영 콘솔
   - 몰입 모드
2. 편집·그룹 패널이면 목록 패널로 돌아간다. 선택한 노트와 입력은 유지된다.
3. 목록 패널에서 아무것도 열려 있지 않으면 앱을 나간다.
   - 단, 선택한 노트가 `saved`가 아니면(`dirty`, `saving`, `error`, `conflict`) 나가지 않고 토스트로 알린다.
   - 같은 조건에서 탭 닫기·새로고침은 `beforeunload` 경고로 막는다.

하단 탭과 화면 안 "목록" 버튼은 이동 기록을 쌓지 않는다. 탭을 여러 번 옮겨도 뒤로가기 순서가 어긋나지 않는다.

## 3. 구현

- `src/lib/backNavigation.ts`: 처리기 스택과 가드 설치
  - 이동 기록에 가드 항목(`__noteBackGuard`) 하나를 유지하고, `popstate`마다 다시 채운다.
  - 가드 상태는 기존 react-router 상태를 그대로 복사해 라우터 인덱스를 깨지 않는다.
  - 해제할 때 history를 되돌리지 않는다(다른 라우트로 이동 중일 수 있음). 다시 설치되면 남은 가드를 재사용한다.
  - 이동 기록 맨 앞이라 나가지 못한 경우, 다음 처리기 등록 때 가드를 다시 건다.
- `src/lib/useBackHandler.ts`: `useBackHandler(active, onBack)` 훅
- `NotesPage`: 모바일일 때만 가드 설치, 패널·몰입 모드·모달 처리기 등록
- 메뉴·팝오버 컴포넌트: 열림 상태를 처리기로 등록

## 4. 검증

- 자동: `tests/back-navigation.test.ts` (처리 순서, 가드 재무장, 이탈 허용·차단, 해제)
- 단위 테스트 환경이 `node`(DOM 없음)라 컴포넌트 연결은 수동 확인으로 대신한다.
- 수동 (Android Chrome, PWA 설치본, iOS Safari):
  1. 편집 → 뒤로가기 → 목록, 입력 유지
  2. 메뉴·공유 팝오버 열림 → 뒤로가기 → 그것만 닫힘
  3. 몰입 모드 → 뒤로가기 → 몰입 모드 해제
  4. 입력 직후 목록에서 뒤로가기 → 토스트, 앱 유지
  5. 저장 완료 후 목록에서 뒤로가기 → 앱 나감
  6. PC에서 동작 변화 없음

## 5. 알려진 제약

- PWA 단독 실행처럼 이동 기록 맨 앞에서 시작하면, 나가기 허용 시 한 번 더 눌러야 앱이 닫힐 수 있다.
- iOS 가장자리 스와이프 뒤로가기는 화면 전환 애니메이션 뒤에 처리되어 깜빡임이 보일 수 있다.
- 브라우저가 강제로 종료하는 경우까지는 막을 수 없다.
